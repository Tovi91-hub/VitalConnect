About VitalConnect

A responsive community wellness site, designed as an IT499 capstone project and built to deploy on restricted static hosting.

The problem

Small support communities — a congregation, a student cohort, a neighbourhood group — coordinate care over group chats and notice boards, where requests scroll away and nobody can tell what has been answered. VitalConnect gives those needs a structured home: a request has a status, a listing can be marked claimed, and a mood entry becomes a trend rather than a passing comment.

The constraint

The hosting available for this project serves static files only — no database, no server-side language, no build step. Every feature here is therefore implemented in HTML, CSS, and vanilla JavaScript, with the browser's LocalStorage standing in for the persistence layer a production deployment would get from a server.

How it is built

Architecture

core.js holds pure logic — hashing, validation, formatting, statistics — with no browser APIs, so it can be unit tested under Node. app.js adds storage, sessions, page chrome, theming, and a small router. auth.js, mood.js, and community.js each own one area of the product and are loaded only by the pages that need them.

Data handling

Passwords are stored as salted, stretched SHA-256 digests rather than plaintext. Collections are versioned, so an older browser's saved data is migrated forward on load rather than being discarded. Corrupt or oversized writes are caught and reported instead of silently failing.
